Align Studio macOS / Apple Silicon candidate

Scope: panel/ is a separate platform port of native/AlignStudio. Windows files are untouched. The ExtendScript engine, bridge and bundled host are byte-identical: no Windows filesystem, shell or executable assumptions exist in the alignment engine. It uses Adobe's shared ExtendScript layer/property APIs. Actual Mac font metrics, expression-engine behavior and CEP activation still require Apple Silicon AE acceptance.

platform.js preserves absolute POSIX paths and decodes file:// URIs once, retaining Unicode, quotes and ordinary percent signs. Local localhost URIs are accepted; remote authorities, relative paths and unresolved traversal are rejected. Windows drive paths remain supported by the isolated port. update.js invokes updater/AlignStudioUpdater.app/Contents/MacOS/AlignStudioUpdater through CEP's native process API with separate arguments. No shell interpolation or Node-enabled CEP setting is required. UI status converts Ctrl/Cmd to Cmd and Alt to Option on macOS without changing engine commands.

Contract: the updater app accepts --settings or --startup, --extension-path, --ae-version and --current-version. Its bundled UpdateKit configuration must select product align-studio, platform macOS-arm64 and the separate update-v1-macos-stable / update-v1-macos-beta feeds. Windows feeds must never be reused for Mac payloads.

Build on macOS: scripts/package.sh <AlignStudioUpdater.app> <output-folder>. Supply ZXPSIGNCMD, CEP_CERTIFICATE and CEP_CERTIFICATE_PASSWORD securely in the release runner. The app must already be arm64 (or universal including arm64), codesigned and notarized as required by distribution policy. The script verifies app signing, signs the exact CEP tree, verifies both ZXP and extracted signed directory, then produces two immutable candidate ZIPs: a root-tree updater payload and an initial installer wrapper. It does not publish a feed or modify CEP debug mode. Private credentials are not part of this source.

The initial Install Align Studio.command uses only the current user's canonical CEP directory under ~/Library/Application Support/Adobe/CEP/extensions. It requires AE to be closed, rejects linked installation paths, copies the signed tree, verifies the helper signature, keeps the original tree in a unique backup and restores that tree on an ordinary failure. No recursive deletion is performed. A hard interruption leaves an install lock for explicit recovery rather than silently overwriting evidence. Preferences outside the extension remain untouched. Later verified update/rollback behavior is owned by UpdateKit. The initial command and Gatekeeper/notarization experience require actual Mac testing before release.

Validation completed on Windows: 22 mocked launcher/path/hint/engine-identity checks plus 31 existing panel/bridge regression checks passed. JavaScript syntax checks passed. No actual subprocess or Adobe API was invoked by these mocks. No macOS compiler/signing/runtime, shell execution or live AE acceptance was performed in this subtask. This is candidate source, not a certified Mac release.
